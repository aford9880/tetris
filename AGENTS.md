# AGENTS.md — правила работы с репозиторием

## Главный принцип
- Минимизируй количество обращений к LLM, команд и любых затратных операций.
- Не выполняй действия, которые не требуются для решения текущей задачи.

## Документация
- Основная документация проекта — `README.md` и `ARCHITECTURE.md`.
- Обновляй их только если изменился пользовательский функционал или архитектура.
- Не изменяй документацию автоматически при мелком рефакторинге.

## Обратная совместимость
- Новый функционал не должен ломать существующий.
- Изменяй существующий код только при необходимости.

## Git
- Правила коммитов находятся в `git.md`.
- Никогда самостоятельно не выполняй:
  - `git add`
  - `git commit`
  - `git push`
  - создание тегов
  - создание Pull Request
- Все действия с Git только после явного разрешения пользователя.
- Не добавляй в репозиторий `__pycache__`, `.venv`, временные файлы и логи.

## Работа с файлами
- Перед удалением или перемещением любого файла покажи список изменений и дождись подтверждения.
- Не переименовывай файлы без необходимости.

## Проверки и запуск

**По умолчанию запрещено выполнять любые затратные команды.**

**Исключение — рефакторинг и правки поведения.** Если изменения затрагивают
код, покрытый тестами (рефакторинг, изменение логики, массовые правки),
разрешено и ожидается запускать быстрые точечные проверки затронутой области:
`ruff`, `mypy`, `pytest` по конкретным файлам/модулям, `npm run lint`.
Правки без прогонов тестов — прямая причина накопившихся ранее 16 красных
тестов в CI. Полные прогоны (вся test-suite, e2e, build) — по-прежнему только
по явному указанию пользователя.

Без явного указания пользователя НЕ запускать:

- unit-тесты;
- интеграционные тесты;
- e2e-тесты;
- `pytest`;
- `npm test`;
- `npm run build`;
- `npm run lint`;
- `ruff`;
- `mypy`;
- `cargo test`;
- `dotnet test`;
- `dotnet build`;
- `docker build`;
- `docker compose up`;
- `docker compose down`;
- запуск приложения;
- перезапуск приложения;
- запуск сервера;
- запуск фронтенда;
- любые benchmark'и;
- любые генерации, индексирования или длительные фоновые процессы.

После внесения изменений просто сообщи:

> Код изменен. Проверки и запуск не выполнялись согласно правилам AGENTS.md.

Если считаешь, что стоит выполнить проверку, сначала предложи конкретную команду и дождись подтверждения.

## Изменения кода

- Делай минимально необходимые изменения.
- Не выполняй рефакторинг, если его не просили.
- Не меняй форматирование файлов, не относящихся к задаче.
- Не исправляй "заодно" найденные проблемы.

## Структура проекта

- Не создавай новые директории без необходимости.
- Не засоряй корень проекта.
- Секреты хранятся только в `.env`.
- Код читает секреты только из переменных окружения.

## План работ

Перед внесением изменений:

1. Кратко опиши план.
2. После подтверждения внеси изменения.
3. Не выполняй дополнительных действий без отдельного запроса.

## Если задача завершена

В конце сообщи:

- какие файлы изменены;
- что именно изменено;
- какие проверки **не запускались**;
- какие команды пользователь может выполнить самостоятельно при необходимости.
